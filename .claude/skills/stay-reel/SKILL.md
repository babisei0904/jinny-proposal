# stay-reel (/숙소릴스)

사용자가 하는 일은 **숙소 고르기**와 **업로드 전 승인** 두 가지뿐이다. 나머지는 이 순서대로 진행한다.
각 단계가 끝날 때마다 한 줄로 진행 상황을 알린다.

이 스킬은 **사용자 Mac 의 Claude Code** 에서 돈다 (Aside 가 Mac 에 있다). 저장소 루트 기준 경로를 쓴다.

| 쓰는 것 | 위치 |
|---|---|
| 조립 프로그램 | `reels/make_reel.py` |
| 벤치마킹 분석 | `reels/analyze_bench.py` |
| 움직임 프롬프트·Flow 설정 | `reels/prompts/flow_motion.json` |
| Aside 지시문 | `reels/prompts/aside.md` |
| 채널별 캡션 규칙 | `reels/prompts/captions.md` |
| 훅 점수·타이밍 (한국어 보정) | `.claude/skills/ig-reel/hookscore.py`, `beats.py` |
| 캡션 검사 | `.claude/skills/ig-caption/caption.py` |
| Aside | MCP 서버 `aside` (`exec` 도구), 없으면 `aside "..."` 명령 |

## 0. 입력 받기

```
/stay-reel 숙소이름 [벤치마킹 영상 경로 ...] [캡션: "..." 또는 캡션 파일 경로] [협찬]
```

- **숙소이름**: 필수. 같은 이름이 여러 곳이면 지역을 한 번 묻는다.
- **벤치마킹 영상**: 선택. 이 숙소를 다룬 남의 릴스 mp4. 여러 개 가능. 대화에 첨부된 파일 경로도 받는다.
- **벤치마킹 캡션**: 선택. 그 영상의 캡션 글.
- **협찬**: 선택. 있으면 `[광고]` 표시와 `#광고` 를 넣는다.

작업 폴더를 만든다. 영문 소문자·숫자·하이픈으로 slug 를 만든다 (한글 경로는 자동화 도구가 못 찾는 경우가 있었다).

```
/Users/<사용자>/stayreel/<slug>/
  input.json        숙소이름, 지역, 협찬 여부, 벤치마킹 파일 경로
  bench/            벤치마킹 영상 분석 결과 (있을 때만)
  info.md           리서치 결과 (출처 포함)
  photos/           수집 사진 01.jpg ...
  sources.csv       사진 출처
  script.txt        대본 (한 줄 = 자막 = 장면, "자막 | 사진")
  prompts.json      사진별 Flow 프롬프트
  clips/            Flow 영상 (사진과 같은 이름)
  reel.json         조립 설정 (표지, 협찬, 계정)
  captions.md       6개 채널 캡션
  out/reel.mp4      완성본
  upload_log.md     업로드 기록
```

## 1. (선택) 벤치마킹 영상·캡션 분석

벤치마킹 영상이 있으면 영상마다:

```bash
python3 reels/analyze_bench.py <영상> --out <폴더>/bench
```

그다음 `*.pairs.jpg` 와 `*.captions.jpg` 를 **직접 보고** `bench/bench.md` 를 쓴다:
- 장면 수, 장면 평균 길이, 첫 장면 길이 (scenes.json 숫자). 자동 검출이 AI 움직임을 전환으로 잘못 잡았으면 pairs.jpg 를 보고 고친다.
- **0초 표지 프레임**이 있는지와 그 제목 (captions.jpg 의 0.0 칸)
- 자막 덩이를 시간순으로 받아 적고, 덩이 수, 덩이당 글자 수(공백 제외), 문장 수를 센다
- 장면마다 장면 종류(`flow_motion.json` 의 프리셋 이름)와 움직임
- 훅 방식 (질문형/가격형/1인칭 문열기), 밤 장면 위치, 마지막 한마디

벤치마킹 캡션이 있으면: 가격, 위치, 시설 같은 **사실 후보**와 해시태그, 말투를 뽑아 bench.md 에 적는다.
캡션의 사실은 2단계에서 다른 출처로 확인되기 전까지 "확인 필요" 로 둔다.

**베끼지 않는다.** 구조, 길이, 장면 순서, 훅 방식은 따라가되 자막 문장과 캡션 문장은 새로 쓴다.
같은 숙소의 남의 문장을 그대로 쓰면 중복 콘텐츠가 되고 원작자 신고 대상이 된다.

벤치마킹이 없으면 기본값을 쓴다 (벤치마크 5개 실측 평균):
장면 18개 · 장면당 1.16초 · 자막 19~20덩이 · 덩이당 7.3자 · 문장 5~6개 · 초당 6.8음절 · 길이 18~21초.

## 2. 숙소 리서치 -> info.md

웹 검색으로 모은다: 정식 이름, 지역·주소, 가는 법, 가격대(평일/주말, 1박 기준), 객실 종류,
핵심 시설(풀, 온천, 사우나, 바베큐, 불멍, 뷰), 주변 볼거리, 예약 방법, 최근 후기에서 반복되는 장점.

- 사실마다 출처 주소를 단다. 출처가 없는 것은 쓰지 않는다.
- 가격은 날짜에 따라 바뀌니 "확인한 날짜와 사이트" 를 같이 적는다.
- 영상에 쓸 **핵심 포인트 3~5개** 를 맨 위에 뽑는다 (이게 대본과 사진 수집 기준이 된다).

## 3. 사진 수집 (Aside) -> photos/, sources.csv

`reels/prompts/aside.md` 의 **A** 를 채워 Aside 에 보낸다.
- 장수: 대본 장면 수의 70% 이상 (보통 12~15장). 같은 사진을 2~3번 다시 쓰는 건 벤치마크도 한다.
- 필요한 장면 목록: 핵심 포인트 + 벤치마킹 장면 종류 + 외관 1장(표지용).
- 끝나면 사진을 직접 열어 확인한다: 흐림, 글자·워터마크, 중복, 세로로 잘랐을 때 주인공이 남는지. 빠진 장면은 다시 요청한다.
- 출처 우선순위는 공식 홈페이지 -> 여행 사이트 -> 블로그. 사용자에게 수집 결과를 출처별 장수로 보고한다.

## 4. 대본 -> script.txt

벤치마킹(또는 기본값)의 숫자에 맞춰 쓴다.

틀:
```
훅 (0~2초)     질문형 "~라고?" / 가격형 "평일 1박 4만 9천원에" / 1인칭 문열기
시설 (2~12초)  "~인데 / ~까지 / ~하고" 로 이어지는 문장. 시설 하나 = 덩이 하나 = 장면 하나
밤 (60~80%)   불멍·야경·조명
마지막 한마디   "저장해 두세요" / "얼른 다녀오세요" / "여기 어때요?" 중 하나
```

규칙:
- 한 줄에 자막 한 덩이, 공백 빼고 5~10자. 빈 줄이나 문장 끝(. ? ! 요 다)에서 내레이션이 끊긴다.
- 숫자는 info.md 에 있는 것만. 없으면 쓰지 않는다.
- 말로 읽어 자연스러운 구어체. "안녕하세요", "오늘은 ~ 알려드릴게요" 금지.
- 쓴 뒤 검사하고 고친다:
  ```bash
  python3 .claude/skills/ig-reel/hookscore.py --hook "<첫 문장>"     # 70점 이상
  python3 .claude/skills/ig-reel/beats.py <폴더>/script.txt --target <목표초>
  ```

**표지 제목**도 같이 정한다 (벤치마크 5개 중 4개가 0초에 표지 프레임을 넣는다. 피드 썸네일로만 보인다):
두 줄, 줄당 공백 빼고 8자 안팎 + (선택) 위쪽 작은 라벨. 예: 라벨 "평일 4만원대 + 조개캐기", 제목 "바다 바로 앞 / 노천탕 카라반".

## 5. 사진 배치 -> script.txt, prompts.json, reel.json

사진을 하나씩 **직접 보고** 장면 종류를 정한다 (`flow_motion.json` 의 presets 키).
대본 줄마다 내용에 맞는 사진을 붙인다: `개별 노천탕에서 | 04.jpg`.
- 첫 줄은 가장 강한 사진 (문 열기·야경·풀). 밤 문장에는 밤 사진.
- 같은 사진 연속 사용 금지. 다시 쓸 때는 다른 문장 사이에.

`prompts.json` 은 쓰인 사진마다:
```json
{"04.jpg": {"preset": "hot_tub", "season_edit": null,
            "prompt": "<presets[preset].prompt> <common_suffix>"}}
```
- 사진 속 움직일 요소(물, 김, 불, 나뭇잎, 커튼)를 프롬프트 앞에 오게 하고, 카메라는 작게.
  (카메라 움직임이 크면 모델이 나뭇잎 같은 작은 움직임을 거의 안 만든다. 테스트에서 확인함.)
- 사진에 없는 사람을 넣는 `people_optional` 은 사용자가 원할 때만.
- 계절 연출이 필요하면 `season_edit` 에 winter_snow / autumn / blue_hour.

`reel.json`:
```json
{"ad": <협찬 여부>, "handle": "@<계정>", "voice": "일반여성2",
 "cover": {"photo": "<외관 사진>", "label": "<라벨 또는 생략>", "lines": ["<1줄>", "<2줄>"]}}
```

## 6. 영상화 (Aside + Google Flow) -> clips/

`flow_motion.json` 의 `flow_settings` (Veo 3.1 Lite, 720p, 4초, 9:16) 로, `aside.md` 의 **B** 를 사진마다 보낸다.
계절 편집이 있는 사진은 편집을 먼저 하고, 편집된 사진을 영상화한다.

사진마다 확인:
```bash
ffprobe -v error -show_entries stream=width,height:format=duration -of csv=p=0 <폴더>/clips/<이름>.mp4
```
- 720x1280 이 아니면 (예: 360p) 설정이 틀린 것이다. `_before.png` 로 설정을 확인하고 다시 만든다.
- 실패는 1번만 다시 시도하고, 그래도 안 되면 그 사진은 클립 없이 둔다 (조립 때 줌·이동 효과로 대신한다).
- 다 끝나면 만든 개수, 실패 개수, 사용 크레딧(보이면)을 알린다.

## 7~8. 조립·자막·목소리 -> out/reel.mp4

```bash
python3 reels/make_reel.py <폴더>
```
- Fish 키와 "일반여성2" 는 영상작업실 설정(settings.json)에서 자동으로 읽는다.
- 출력의 장면 평균 길이와 초당 음절이 벤치마킹(또는 기본값)과 크게 다르면 대본 길이를 고쳐 다시 만든다.

## 9. 캡션 -> captions.md

`reels/prompts/captions.md` 규칙대로 6개 채널을 쓴다: 인스타그램 릴스, 스레드, 유튜브 쇼츠, 틱톡, 네이버 클립, 샤오홍슈.
인스타 캡션은 `python3 .claude/skills/ig-caption/caption.py` 로 검사한다.

## ✋ 승인 받기 (건너뛰지 않는다)

사용자에게 보여준다:
- `out/reel.mp4` (파일로 보내기), 표지 제목, 길이, 장면 수
- captions.md 전체
- info.md 핵심 포인트와 출처, sources.csv 의 출처별 사진 수

"승인" 또는 "올려" 같은 **명시적 답**이 있을 때만 10단계로 간다. 수정 요청이면 해당 단계로 돌아간다.
채널을 골라 승인하면 그 채널만 올린다.

## 10. 업로드 (Aside) -> upload_log.md

`aside.md` 의 **C** 를 채널마다 보낸다. 순서: 인스타그램 -> 스레드 -> 유튜브 쇼츠 -> 틱톡 -> 네이버 클립 -> 샤오홍슈.
- 각 채널 **처음 몇 번은 비공개 또는 임시저장**으로 올린다 (사용자가 공개로 바꾸라고 할 때까지).
- 협찬이면 각 채널의 유료 광고 표시를 켠다. AI 생성 표시 항목이 있으면 켠다.
- 게시 버튼 직전에 Aside 가 멈추고 확인을 받는다. 한 채널씩, 몰아서 올리지 않는다.
- 결과(채널, 시각, 공개 범위, 게시물 주소, 실패 사유)를 `upload_log.md` 에 남기고 사용자에게 표로 보고한다.

## 하지 않는 것

- 사실을 지어내지 않는다 (가격, 시설, 수상 내역, 후기 수치). 모르면 빼거나 `{{확인 필요}}` 로 표시하고 승인 때 알린다.
- 승인 없이 게시하지 않는다.
- 벤치마킹 영상의 자막·캡션 문장을 그대로 옮기지 않는다.
